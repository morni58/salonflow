## Часть B. Supabase — база данных (строго по порядку)

1. Открой проект: https://supabase.com → твой проект.
2. Слева: **SQL Editor** → **New query**.
3. Выполни файлы **по очереди** (каждый — отдельным запуском **Run**):

   | № | Файл в репозитории | Что добавляет |
   |---|-------------------|----------------|
   | 1 | `backend/migrations/001_initial.sql` | Таблицы салона, услуг, записей, пользователей бота и т.д. |
   | 2 | `backend/migrations/002_site_crm.sql` | Поля сайта: `working_days`, `site_content`, `contact_json` и др. |
   | 3 | `backend/migrations/003_masters.sql` | Мастера, график мастера, связь услуга–мастер, `master_id` в записях |

   **Важно:** если база уже живая и `001` давно выполнен — **не выполняй `001` снова** (будут ошибки «already exists»). Тогда выполняй только **`002` и `003`**, если они ещё не применялись.

4. Проверка: **Table Editor** — должны быть таблицы `tenants`, `services`, `bookings`, и после 003 — **`masters`**, **`master_schedule_exceptions`**, **`service_masters`**. У `bookings` должна появиться колонка **`master_id`** (может быть `NULL` у старых строк).

## Часть C. Supabase — Storage (бакеты)

Слева: **Storage** → **New bucket** для каждого имени. У всех ниже включи **Public bucket** (публичные URL для сайта и бота).

| Имя бакета | Назначение |
|------------|------------|
| `portfolio` | Фото портфолио из бота |
| `reviews` | Скриншоты отзывов |
| `logos` | Логотипы (если используешь загрузку в Storage) |
| `service-photos` | Фото **услуг** из бота (каталог) |
| `master-photos` | Фото **мастеров** из `/my_profile` |

Если бакет уже создан — второй раз не создавай.

## Часть E. Бэкенд (API + логика бота)

1. Перейди в каталог:

   ```powershell
   cd C:\Users\XE\Desktop\salonflow\backend
   ```

2. Виртуальное окружение (по желанию, но удобно):

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\activate
   ```

3. Зависимости:

   ```powershell
   pip install -r requirements.txt
   ```

4. Файл **`.env`** в папке `backend` (если нет — скопируй из `.env.example` и заполни):

   | Переменная | Откуда взять |
   |------------|----------------|
   | `SUPABASE_URL` | Supabase → Settings → API → Project URL |
   | `SUPABASE_KEY` | **service_role** (секретный ключ, не anon!) |
   | `BASE_URL` | Публичный URL твоего API, например `https://api.salonflow.kz` или для локалки `http://127.0.0.1:8000` |
   | `ENCRYPTION_KEY` | Длинная случайная строка; для Fernnet можно сгенерировать отдельно (см. документацию проекта) |
   | `REDIS_URL` | Опционально; для бота на нескольких инстансах — URL Redis (иначе FSM в памяти) |

5. Запуск локально:

   ```powershell
   python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
   ```

6. Проверка в браузере или curl:

   - `http://127.0.0.1:8000/api/health` → `{"status":"ok",...}`
   - `http://127.0.0.1:8000/api/tenant?subdomain=demo` → JSON салона (если есть демо-tenant)

7. **Продакшен (сервер / Docker / Cloud Run):**  
   Залей обновлённый код, пересобери образ при необходимости и **перезапусти сервис**. Пока старый процесс работает — новый код не выполняется.

## Часть G. Telegram-бот и webhook

1. В Supabase таблица **`tenants`**: у нужного салона в поле **`bot_token_encrypted`** должен быть токен бота (как ты уже сохранял — в т.ч. зашифрованным, если так настроено в проекте).

2. Таблица **`users`**: твой `telegram_user_id`, `tenant_id`, роль `owner` или `admin`.

3. **Webhook:** бэкенд при старте выставляет webhook на  
   `{BASE_URL}/api/webhook/tg/{tenant_id}`  
   Значит **`BASE_URL` в `.env`** должен быть **реальным HTTPS-адресом**, доступным из интернета (не `localhost` для продакшена).

4. После обновления бэкенда бот подхватит новые команды (`/help`, `/add_staff`, `/my_schedule` и т.д.) при следующем старте API.

## Часть I. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| Ошибки SQL «already exists» | Миграция уже была — не дублируй `CREATE TABLE`. |
| Слотов нет при выборе мастера | Миграция `003`, в таблице `masters` есть активные мастера, у мастера заданы часы/дни. |
| Загрузка фото в боте падает | Создан бакет `service-photos` или `master-photos`, права у service role. |
| Бот не отвечает | Токен в `tenants`, webhook URL, `BASE_URL`, firewall. |
| Сайт не видит API | CORS на бэкенде, URL API во фронте, HTTPS. |

## Часть J. Краткая шпаргалка «только обновить код»

1. `git pull` (или копирование файлов).  
2. Supabase: новые миграции SQL **по одной**, новые бакеты.  
3. `backend`: `pip install -r requirements.txt` → перезапуск.  
4. `frontend`: `npm install` → `npm run build` → деплой `dist`.  

После этого сегодняшние правки в коде начинают работать в твоих программах и на сайте.
